# Quickstart: 힐끔 MVP 검증 가이드

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md)

## 사전 준비

- JDK 11 이상, Android SDK 36, 에뮬레이터 2대 또는 실기기 2대(Android 8.0 이상, API 26)
- `remote` 변형을 쓰려면 `local.properties`에 두 서버 주소가 필요하다: `hil.springBaseUrl`(방·스탬프·소원권), `hil.nodeBaseUrl`(게임). `google-services.json`은 푸시 연동(⚠️G11) 때부터 필요하다.
- `fake` 변형은 서버 없이 동작한다. 한 기기 안에서 상대 행동을 디버그 메뉴로 흉내 낸다(research R12).

## 빌드 / 테스트 명령

```bash
./gradlew testFakeDebugUnitTest            # Policy·UseCase·ViewModel·Repository(MockWebServer) 단위 테스트
./gradlew connectedFakeDebugAndroidTest    # Compose UI 흐름 테스트 (Fake Repository)
./gradlew installFakeDebug                 # 서버 없이 데모
./gradlew installRemoteDebug               # 실제 서버로 2기기 E2E
```

## 2기기 수동 E2E 시나리오 (`remote`)

> 선행 조건: 서버 갭 G1(참여자의 gameId), G2(내 미션 조회), G8(받은 소원권 요청 조회)이 반영되어 있어야 한다. 반영 전에는 `fake` 변형으로 같은 시나리오를 진행한다. 3단계의 기기 알림과 '미접속' 표시, 8단계의 자동 취소는 G11·G7·G12가 반영된 뒤에 확인한다.

기기 A(방장)와 B(참여자)로 진행한다. 각 단계는 스펙 Acceptance Scenario와 대응한다.

1. **초대 (US1)**: A에서 '시작하기'를 누르고 코드를 복사한다. B에서 잘못된 코드를 넣으면 재입력 안내가 나와야 한다. B에서 올바른 코드를 넣으면 A 화면이 '상대 입장'으로 바뀌어야 한다(3초 이내, SC-004). 기기 C로 같은 코드를 넣으면 '이미 사용된 코드' 안내가 나와야 한다.
2. **설정 (US2)**: A에서 오프라인·미션 2개로 설정한다. 두 사람 모두 미션 2개와 벌칙 1개를 고른다. A만 먼저 끝내면 A 화면에 '상대 대기'가 나와야 한다. 두 사람이 모두 끝내면 둘 다 진행 화면으로 넘어가야 한다. 이 사이에 상대의 선택이 화면에 한 번도 보이지 않아야 한다(SC-003).
3. **종료 (US3)**: A에서 종료를 요청하고 B에서 거절한다. 두 기기 모두 진행 화면으로 돌아가야 한다. B의 앱을 강제 종료한 뒤 A에서 다시 요청하면 A 화면에 '상대 미접속'이 나와야 한다. B 기기에 시스템 알림이 와야 하고, 알림을 누르면 종료 확인으로 이동해야 한다. B에서 동의하면 두 기기 모두 추리 화면으로 넘어가야 한다.
4. **추리·채점 (US4)**: 빈 칸이 있으면 제출할 수 없어야 하고, 31자째 글자는 입력되지 않아야 한다. 비행기 모드에서 제출을 시도한 뒤 네트워크를 복구하고 재시도하면 추리가 한 번만 저장되어야 한다.
5. **결산 (US5)**: A는 2개 수행·추리 1개 정답, B는 1개 수행·추리 2개 정답으로 채점한다. 두 기기 모두 40 대 35, A 승리로 표시되어야 하고 A가 고른 벌칙만 공개되어야 한다. 동점이 나오도록 다시 채점하면 가위바위보 화면이 나와야 하고, 비기면 다시 해야 한다.
6. **스탬프·소원권 (US6)**: A가 3번 이기면 교환 버튼이 활성화되어야 한다. 교환하면 D-day가 표시되어야 한다. A에서 사용을 누르면 B에 승인 요청 알림이 와야 한다. B에서 거절하면 A에 소원권이 그대로 남아야 하고, B에서 승인하면 소원권이 사라져야 한다.
7. **복구 (FR-008)**: 각 단계마다 앱을 강제 종료했다가 다시 열면 같은 단계로 돌아와야 한다.
8. **자동 취소 (FR-052a)**: 서버의 테스트용 시계 조작 기능이 있으면 24시간을 경과시킨다. 두 기기 모두 대기실로 돌아가 취소 안내가 나와야 한다. 이 검증은 서버팀과 함께 진행한다.
