# Feature Specification: 힐끔 MVP — 연인 미션·추리 데이트 게임

## 개요

힐끔은 연인 두 사람이 각자 비공개 미션(평소와 다른 행동)을 수행하고, 서로를 관찰해 상대의 미션을 추리한 뒤 결과를 확인하는 데이트 게임이다. 탐정·기밀 문서 콘셉트는 화면 표현일 뿐이며 핵심 경험은 **미션**과 **관찰**이다.

MVP 목표는 두 사용자가 각자 기기에서 **방 생성 → 설정 → 진행 → 종료 동의 → 추리 → 채점 → 결산 → 스탬프 적립**까지 한 라운드를 끝까지 완료하는 것이다. 방 정원은 2명이다.

## Clarifications

### Session 2026-11-21

- Q: 점수 공식·점수 귀속·여러 미션 집계 방식은? → A: (PRD 4.7 갱신 반영) 모든 미션에 같은 배점을 준다. 본인이 수행(O)한 미션 1개당 수행자 +15점, 상대 미션에 대한 추리가 정답(O)으로 판정되면 1개당 추리자 +10점. 개인 점수 = 수행한 미션 수 × 15 + 맞힌 미션 수 × 10. 개인 최고점은 미션 1/2/3개일 때 25/50/75점이다.
- Q: 소원권 사용 시 상대의 승인이 있어야 소진되는가? → A: 상대가 승인해야 소진된다. 상대는 거절할 수 있고, 거절하면 소원권이 그대로 남아 다시 사용할 수 있다.
- Q: 라운드 중도 포기·이탈 처리는? → A: 두 참가자 모두 24시간 동안 아무 활동이 없으면 라운드가 자동 취소된다(수동 중단 기능 없음).
- Q: 앱을 사용하지 않을 때 기기 알림 범위는? → A: 상대의 응답이 필요한 이벤트(상대 입장, 종료 요청, 소원권 승인 요청)만 기기 알림으로 보낸다. 그 밖의 진행 상황은 앱을 열었을 때 화면에 반영한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 방 만들고 연인 초대하기 (Priority: P1)

한 사용자가 앱을 처음 열어 ‘시작하기’로 방을 만들고 초대 코드를 복사해 연인에게 전달한다. 연인은 ‘초대 코드 입력’으로 코드를 입력해 같은 방에 들어온다. 두 사람이 모두 입장하면 홈/대기실에서 서로의 입장 상태를 확인한다.

**Why this priority**: 두 사람이 같은 방에 연결되지 않으면 이후 어떤 기능도 동작할 수 없는 전제 조건이다.

**Independent Test**: 두 기기에서 방 생성 → 코드 복사 → 코드 입력 → 양쪽 대기실에 2명 표시까지 확인하면 독립적으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 앱을 처음 실행한 사용자, **When** ‘시작하기’를 누른다, **Then** 새 방이 만들어지고 초대 코드와 복사 버튼, ‘상대 대기 중’ 상태가 표시된다.
2. **Given** 방장이 초대 코드를 공유한 상태, **When** 상대가 ‘초대 코드 입력’에서 올바른 코드를 입력한다, **Then** 상대는 같은 방에 입장하고 방장 화면은 ‘상대 입장’으로 바뀐다.
3. **Given** 코드 입력 화면, **When** 빈 값이나 존재하지 않는 코드를 입력한다, **Then** 입장되지 않고 재입력 안내가 표시된다.
4. **Given** 이미 2명이 입장한 방의 코드, **When** 제3자가 해당 코드를 입력한다, **Then** 입장되지 않고 ‘이미 사용된 코드’ 안내가 표시된다.
5. **Given** 방에 입장해 있던 사용자, **When** 앱을 종료했다가 다시 연다, **Then** 같은 방과 진행 중이던 단계로 복귀한다.

### User Story 2 - 비공개로 미션·벌칙 설정하기 (Priority: P1)

방장이 ‘미션 시작’을 눌러 라운드 유형(온라인/오프라인)과 미션 개수(1–3개)를 정한다. 이후 두 사람은 각자 화면에서 자신이 수행할 미션을 정해진 개수만큼 고르고, 상대가 패배 시 수행할 벌칙 1개를 고른다. 상대가 고른 미션·벌칙은 결산 공개 전까지 절대 보이지 않는다.

**Why this priority**: 비공개 미션이 게임의 핵심이며, 설정이 없으면 진행·추리가 성립하지 않는다.

**Independent Test**: 두 기기에서 각자 미션·벌칙을 고르고, 어느 기기 화면에도 상대의 선택이 노출되지 않은 채 양쪽 모두 진행 단계로 넘어가는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 두 사람이 입장한 대기실, **When** 방장이 유형과 미션 개수(예: 2개)를 정하고 완료한다, **Then** 양쪽 모두 미션 선택 화면으로 이동하고 각자 정확히 2개를 골라야 완료할 수 있다.
2. **Given** 미션 선택 화면, **When** 정해진 개수보다 적거나 많이 선택한다, **Then** 완료할 수 없고 재선택 안내가 표시된다.
3. **Given** 한 사람만 미션·벌칙 선택을 완료한 상태, **When** 완료한 사람이 화면을 본다, **Then** ‘상대 설정 대기 중’이 표시되고 자신의 선택은 유지된다.
4. **Given** 양쪽 모두 미션·벌칙 선택을 완료, **When** 마지막 사람이 완료한다, **Then** 두 기기 모두 진행 단계로 전환된다.
5. **Given** 설정 단계 어느 시점이든, **When** 사용자가 화면을 확인한다, **Then** 상대가 선택한 미션과 벌칙은 어떤 형태로도 표시되거나 전달되지 않는다.

### User Story 3 - 데이트 진행과 종료 합의 (Priority: P1)

진행 중에는 각자 자신의 미션만 보며 데이트를 즐긴다. 한 사람이 ‘종료’를 요청하면 상대에게 확인 요청이 가고, 상대가 동의하면 추리 단계로 넘어간다. 거절하면 진행이 계속된다.

**Why this priority**: 진행과 종료 합의는 라운드의 흐름을 잇는 필수 단계다.

**Independent Test**: 한쪽에서 종료 요청 → 상대 기기에서 수신 → 동의/거절에 따라 양쪽 화면이 추리 단계 또는 진행 화면으로 전환되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 진행 단계, **When** 사용자가 진행 화면을 본다, **Then** 자신의 미션 목록과 진행 상태, 종료 버튼만 표시된다.
2. **Given** 진행 단계, **When** A가 종료를 요청한다, **Then** A에게는 ‘응답 대기 중’이, B에게는 종료 확인(동의/거절)이 표시된다.
3. **Given** B가 종료 확인을 받은 상태, **When** B가 동의한다, **Then** 두 기기 모두 추리 입력 단계로 전환된다.
4. **Given** B가 종료 확인을 받은 상태, **When** B가 거절한다, **Then** 두 기기 모두 기존 진행 화면으로 돌아가고 A에게 거절 사실이 안내된다.
5. **Given** A가 종료 요청을 여러 번 누르거나 양쪽이 동시에 요청한다, **When** 요청이 처리된다, **Then** 종료 요청은 한 건으로만 처리된다.
6. **Given** A가 종료 요청을 보냈고 B가 앱에 접속해 있지 않다, **When** A가 화면을 본다, **Then** ‘상대 미접속’이 ‘응답 대기 중’과 구분되어 표시된다.

### User Story 4 - 상대 미션 추리와 채점 (Priority: P1)

종료에 합의하면 각자 상대의 미션을 미션 개수만큼 텍스트(각 30자 이내)로 추리해 한 번에 제출한다. 이후 각자 자기 미션을 실제로 수행했는지 O/X로 체크하고, 상대가 쓴 추리가 내 미션과 맞는지 O/X로 판정한다.

**Why this priority**: 추리·채점이 있어야 점수와 승패가 결정된다.

**Independent Test**: 두 기기에서 추리 제출 → 상대 추리 수신 → 수행 O/X·정답 O/X 판정까지 마치면 양쪽 모두 결산으로 넘어가는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 상대 미션이 2개인 추리 화면, **When** 사용자가 두 칸 모두 입력하고 제출한다, **Then** 추리가 저장되어 상대에게 전달되고 이후 수정할 수 없다.
2. **Given** 추리 화면, **When** 한 칸이라도 비어 있다, **Then** 제출할 수 없다.
3. **Given** 추리 입력 칸, **When** 30자를 초과해 입력하려 한다, **Then** 30자까지만 입력된다.
4. **Given** 한쪽만 추리를 제출한 상태, **When** 제출한 사람이 화면을 본다, **Then** ‘상대 추리 대기 중’이 표시된다.
5. **Given** 양쪽 추리 제출 완료, **When** 채점 화면에 들어간다, **Then** 내 미션별로 ‘수행 O/X’와 ‘상대 추리 정답 O/X’를 판정할 수 있다.
6. **Given** 한쪽만 채점을 완료한 상태, **When** 완료한 사람이 화면을 본다, **Then** 결산은 공개되지 않고 ‘상대 채점 대기 중’이 표시된다.
7. **Given** 제출·채점 중 통신이 실패한 상태, **When** 재시도한다, **Then** 결과는 한 번만 반영된다.

### User Story 5 - 결산과 동점 가위바위보 (Priority: P1)

양측 채점이 끝나면 점수가 계산되고, 서로의 미션·추리·수행 여부·최종 점수가 공개된다. 승자와 패자가 정해지면 승자가 골라 둔 벌칙이 공개되어 패자가 수행할 벌칙으로 안내된다. 동점이면 승자가 나올 때까지 가위바위보를 한다.

**Why this priority**: 결산은 라운드의 보상과 재미가 완성되는 순간이다.

**Independent Test**: 채점 완료 후 두 기기에 동일한 점수·승패·벌칙이 표시되는지, 동점일 때 가위바위보로 승부가 결정되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 양측 채점 완료, **When** 결산이 공개된다, **Then** 두 기기에 양쪽 미션, 추리, 수행 여부, 정답 여부, 최종 점수가 동일하게 표시된다.
2. **Given** 미션 2개 라운드에서 A는 2개 수행·추리 1개 정답, B는 1개 수행·추리 2개 정답, **When** 결산이 공개된다, **Then** A는 40점(2×15 + 1×10), B는 35점(1×15 + 2×10)으로 표시되고 A가 승자가 된다.
3. **Given** 점수가 다른 경우, **When** 결산이 공개된다, **Then** 점수가 높은 사람이 승자로 표시되고, 승자가 선택한 벌칙이 패자의 벌칙으로 공개된다. 패자가 선택한 벌칙은 공개하지 않는다.
4. **Given** 점수가 같은 경우, **When** 결산 단계에 들어간다, **Then** 승패 공개 전에 가위바위보 화면이 양쪽에 표시된다.
5. **Given** 가위바위보 화면, **When** 두 사람이 각자 선택을 마친다, **Then** 양쪽 선택이 동시에 공개되고 승패가 결정된다.
6. **Given** 가위바위보 결과가 비김, **When** 결과가 공개된다, **Then** 승자가 결정될 때까지 다시 가위바위보를 진행한다.

### User Story 6 - 승리 스탬프와 소원권 (Priority: P2)

승자는 스탬프 1개를 받는다(최대 3개). 3개가 모이고 소원권이 없으면 교환해 소원권 1장(1개월 유효)을 받는다. 소원권을 사용하면 상대에게 알림이 간다.

**Why this priority**: 반복 플레이 동기를 주는 장기 보상이지만, 한 라운드 완주 자체는 이 기능 없이도 가능하다.

**Independent Test**: 승리를 반복해 스탬프 3개 → 교환 → 소원권 D-day 표시 → 사용 시 상대 알림 수신까지 확인한다.

**Acceptance Scenarios**:

1. **Given** 스탬프 2개 보유자가 승리, **When** 결산이 끝난다, **Then** 스탬프가 3/3이 되고 (소원권이 없다면) 교환 버튼이 활성화된다.
2. **Given** 스탬프 3개·소원권 없음, **When** 교환을 누른다, **Then** 스탬프 3개가 차감되고 발급일 기준 1개월 유효한 소원권 1장이 발급되며 D-day가 표시된다.
3. **Given** 스탬프 3개·소원권 보유, **When** 스탬프 화면을 본다, **Then** 교환 버튼은 비활성이며 ‘스탬프가 가득 차 추가 승리해도 스탬프를 받을 수 없다’는 경고가 표시된다.
4. **Given** 스탬프 3개 상태에서 다시 승리, **When** 결산이 끝난다, **Then** 스탬프는 3개로 유지된다.
5. **Given** 소원권 보유, **When** 사용을 누르고 확인한다, **Then** 상대에게 사용 승인 요청 알림이 전달되고, 요청자 화면에는 '승인 대기 중' 상태가 표시된다(전송 실패 시 실패 안내와 재시도).
6. **Given** 소원권 사용 승인 요청을 받은 상대, **When** 상대가 승인한다, **Then** 소원권이 소진되고 요청자에게 '사용 완료'가 표시된다.
7. **Given** 소원권 사용 승인 요청을 받은 상대, **When** 상대가 거절한다, **Then** 소원권은 소진되지 않고 보유 상태로 돌아가며 요청자에게 거절 사실이 안내된다.
8. **Given** 소원권 유효기간 경과, **When** 사용자가 스탬프 화면을 연다, **Then** 별도 경고 없이 소원권이 사라져 있다.
9. **Given** 한 라운드의 결산, **When** 결산 화면을 다시 열거나 통신이 재시도된다, **Then** 승자 스탬프는 라운드당 한 번만 적립된다.

### User Story 7 - 이용 방법 확인 (Priority: P3)

대기실 우측 상단의 ?를 눌러 간단한 게임 규칙을 확인하고 뒤로 돌아온다.

**Why this priority**: 처음 사용하는 커플의 이해를 돕지만 핵심 흐름에는 영향이 없다.

**Independent Test**: 대기실에서 ? → 규칙 화면 → 뒤로 가기로 대기실 복귀를 확인한다.

**Acceptance Scenarios**:

1. **Given** 홈/대기실, **When** ? 아이콘을 누른다, **Then** 게임 규칙 화면이 표시되고 뒤로 가기로 대기실에 돌아온다.

### Edge Cases

- 방장만 방을 만들고 상대가 아직 입장하지 않은 경우: 코드는 방이 성립(2명 입장)하기 전까지 계속 유효하며, 설정 시작은 불가하다.
- 설정·진행·추리·채점 중 한 사람이 앱을 종료하거나 연결이 끊긴 경우: 이미 저장된 선택·제출은 유지되고, 재접속 시 현재 라운드 단계로 복귀한다.
- 라운드에서 두 참가자 모두 24시간 동안 활동이 없는 경우: 라운드가 자동 취소된다. 점수·승패·스탬프 없이 종료되고, 두 사람 모두 다음 접속 때 대기실에서 취소 안내를 받는다. 진행 단계에도 똑같이 적용된다.
- 결산 공개 이후(승패 확정 후): 자동 취소 대상이 아니며 결과와 스탬프는 유지된다.
- 선택 가능한 미션 목록이 비었거나 선택 개수보다 적은 경우: 진행 불가 안내를 표시한다.
- 양쪽이 동시에 종료를 요청한 경우: 한 건으로 처리하고, 먼저 접수된 요청 기준으로 상대 동의를 받는다(동시 요청은 상호 동의로 간주).
- 종료 요청 후 상대가 응답하지 않는 경우: 요청자는 대기 상태를 유지하며 요청을 취소하고 진행 화면으로 돌아갈 수 있다. 응답 없이 24시간이 지나면 라운드 자동 취소 규칙을 따른다.
- 같은 추리·채점 결과가 네트워크 재전송으로 여러 번 도착하는 경우: 한 번만 저장·반영한다.
- 가위바위보에서 한 사람만 선택하고 다른 사람이 미접속인 경우: 선택한 쪽은 대기 표시, 상대 재접속 시 이어서 진행한다.
- 앱을 삭제·재설치한 경우: 기존 방에 복귀할 수 없으며, 새 방을 만들어야 한다(방 삭제 수단은 MVP에 없음).
- 소원권 승인 대기 중에 유효기간이 지난 경우: 소원권은 만료로 삭제되고 대기 중인 요청은 무효가 된다.
- 소원권 보유 중 스탬프가 3개 가득 찬 상태에서 추가 승리: 스탬프는 늘지 않고 경고 문구가 표시된다.

## Requirements *(mandatory)*

### Functional Requirements

**초기 설정 / 초대**

- **FR-001**: 시스템은 첫 진입 시 ‘시작하기’와 ‘초대 코드 입력’ 두 가지 선택지를 제공해야 한다.
- **FR-002**: ‘시작하기’를 선택한 사용자(방장)에게 새 방과 고유 초대 코드를 생성하고, 코드를 확인·복사할 수 있게 해야 한다.
- **FR-003**: 사용자(참여자)는 초대 코드를 입력해 해당 방에 입장할 수 있어야 한다.
- **FR-004**: 시스템은 빈 코드·존재하지 않는 코드 입력 시 입장을 거부하고 재입력을 안내해야 한다.
- **FR-005**: 시스템은 정원(2명)이 찬 방의 코드 입력 시 입장을 거부하고 ‘이미 사용된 코드’로 안내해야 한다.
- **FR-006**: 초대 코드는 두 번째 참가자가 입장해 방이 성립되기 전까지 유효해야 한다.
- **FR-007**: 방장 화면은 상대 대기·상대 입장 상태를 실시간으로 표시해야 한다.
- **FR-008**: 시스템은 사용자가 앱을 다시 열거나 재접속하면 같은 방과 현재 라운드 단계로 복귀시켜야 한다.
- **FR-009**: 참가자 2명이 모두 입장하기 전에는 라운드 설정을 시작할 수 없어야 한다.

**홈 / 대기실**

- **FR-010**: 대기실은 참가자 정보와 현재 진행 현황, ‘미션 시작’ 아이콘, 이용 방법(?) 진입, 홈↔스탬프 화면 전환을 제공해야 한다.

**라운드 설정 (방 생성)**

- **FR-011**: 방장은 ‘미션 시작’으로 새 라운드를 시작하고, 라운드 유형(온라인/오프라인)과 미션 개수(1–3개)를 정할 수 있어야 한다.
- **FR-012**: 유형 또는 개수를 선택하지 않으면 다음 단계로 진행할 수 없고 안내가 표시되어야 한다.
- **FR-013**: 참여자는 방장이 라운드 설정을 마칠 때까지 대기 상태를 표시받아야 한다.

**미션 / 벌칙 설정**

- **FR-014**: 각 사용자는 선택한 유형에 맞는 미션 목록에서 라운드 미션 개수와 정확히 같은 수의 미션을 선택해야 한다.
- **FR-015**: 각 사용자는 상대가 패배했을 때 수행할 벌칙을 정확히 1개 선택해야 한다.
- **FR-016**: 선택값이 없거나 유효하지 않거나 목록이 비어 있으면 완료할 수 없고 재선택 안내가 표시되어야 한다.
- **FR-017**: 한쪽만 설정을 완료하면 해당 사용자의 선택은 유지되고 ‘상대 대기’가 표시되어야 한다.
- **FR-018**: 양쪽 설정이 완료되면 두 사용자 모두 자동으로 진행 단계로 전환되어야 한다.
- **FR-019**: 상대가 선택한 미션과 벌칙은 결산 공개 전까지 상대 기기의 화면·알림·전달 데이터 어디에도 포함되어서는 안 된다.

**진행 / 종료**

- **FR-020**: 진행 화면에는 본인의 미션, 진행 상태, 종료 버튼만 표시해야 한다.
- **FR-021**: 사용자는 종료를 요청할 수 있고, 상대는 종료 확인(동의/거절)을 받아야 한다.
- **FR-022**: 상대가 동의하면 두 사용자 모두 추리 단계로, 거절하면 두 사용자 모두 진행 화면으로 전환되어야 하며 요청자에게 거절이 안내되어야 한다.
- **FR-023**: 종료 요청자는 ‘응답 대기 중’과 ‘상대 미접속’을 구분해 확인할 수 있어야 한다.
- **FR-024**: 중복·동시 종료 요청은 한 건으로만 처리되어야 한다.
- **FR-025**: 종료 요청자는 상대 응답 전까지 요청을 취소할 수 있어야 한다.

**추리**

- **FR-026**: 각 사용자는 상대 미션 개수만큼의 추리 입력란을 한 화면에서 작성하고 한 번에 제출해야 한다.
- **FR-027**: 각 추리 입력은 1자 이상 30자 이하여야 하며, 빈 칸이 있으면 제출할 수 없어야 한다.
- **FR-028**: 제출된 추리는 상대(미션 소유자)에게 전달되며 이후 수정할 수 없어야 한다.
- **FR-029**: 한쪽만 제출하면 제출한 쪽에 ‘상대 대기’가 표시되어야 한다.
- **FR-030**: 재전송된 제출은 중복 저장되지 않아야 한다.

**채점**

- **FR-031**: 각 사용자는 자신의 미션별로 실제 수행 여부를 O/X로 체크해야 한다(자기 보고, 별도 검증 없음).
- **FR-032**: 각 사용자는 상대가 내 미션에 대해 입력한 추리를 보고 미션별 정답 여부를 O/X로 판정해야 한다.
- **FR-033**: 양측 채점이 모두 끝나기 전에는 결산이 공개되지 않아야 하며, 먼저 끝낸 쪽에는 대기가 표시되어야 한다.
- **FR-034**: 통신 실패 시 재시도를 제공하고, 채점 결과가 중복 반영되지 않아야 한다.

**결산**

- **FR-035**: 시스템은 각 사용자의 점수를 `본인이 수행(O)한 미션 수 × 15점 + 상대 미션 중 내 추리가 정답(O)으로 판정된 미션 수 × 10점`으로 계산해야 한다. 추리 점수는 미션 소유자의 정답 판정만 기준으로 하며, 그 미션의 실제 수행 여부와는 무관하다. 개인 최고점은 미션 1/2/3개일 때 25/50/75점이다.
- **FR-036**: 결산은 양쪽 미션, 추리 내용, 수행 여부, 정답 여부, 최종 점수를 두 사용자에게 동일하게 공개해야 한다.
- **FR-037**: 점수가 높은 사용자를 승자로, 낮은 사용자를 패자로 표시하고, 승자가 선택한 벌칙을 패자가 수행할 벌칙으로 공개해야 한다. 패자가 선택했던 벌칙은 공개하지 않는다.
- **FR-038**: 벌칙은 결산 화면에서 안내만 하며, 벌칙 수행 여부의 확인·기록은 MVP 범위에 포함하지 않는다.
- **FR-039**: 두 기기의 결산 결과(점수·승자·벌칙)는 항상 일치해야 한다.

**동점 처리**

- **FR-040**: 점수가 같으면 승패 공개 전에 가위바위보를 진행해야 한다.
- **FR-041**: 가위바위보는 각자 비공개로 선택하고, 양쪽 선택이 끝난 뒤 동시에 공개해야 한다.
- **FR-042**: 비기면 승자가 결정될 때까지 가위바위보를 반복해야 한다.

**스탬프 / 소원권**

- **FR-043**: 라운드 승자에게 스탬프 1개를 라운드당 한 번만 적립해야 하며, 보유량은 최대 3개다.
- **FR-044**: 스탬프 3개 보유·소원권 미보유 시 교환 버튼을 활성화해야 한다.
- **FR-045**: 교환 시 스탬프 3개를 차감하고 소원권 1장을 발급해야 한다. 소원권은 1인당 최대 1장 보유할 수 있다.
- **FR-046**: 소원권은 발급일로부터 1개월간 유효하며 남은 기간을 D-day로 표시해야 한다.
- **FR-047**: 스탬프가 가득 차고 소원권을 이미 보유한 경우, 추가 승리 시 스탬프를 받을 수 없음을 알리는 경고 문구를 표시해야 한다.
- **FR-048**: 사용자가 소원권 사용을 확인하면 상대에게 사용 승인 요청을 보내고, 요청자에게 승인 대기·완료·실패 상태를 표시해야 한다.
- **FR-048a**: 상대는 소원권 사용 요청을 승인하거나 거절할 수 있어야 한다. 승인하면 소원권이 소진되고, 거절하면 소원권은 보유 상태로 돌아가 다시 사용할 수 있다. 승인 요청 중에는 같은 소원권으로 중복 요청할 수 없다.
- **FR-049**: 유효기간이 지난 소원권은 별도 알림 없이 삭제되어야 한다.

**라운드 자동 취소**

- **FR-052a**: 결산 공개 전 라운드에서 두 참가자 모두 24시간 동안 활동(선택, 제출, 요청, 응답, 채점 등 라운드 상태를 바꾸는 행동)이 없으면 시스템은 그 라운드를 자동 취소해야 한다.
- **FR-052b**: 자동 취소된 라운드는 점수·승패·스탬프를 남기지 않아야 하며, 두 참가자 모두 대기실에서 취소 안내를 받고 새 라운드를 시작할 수 있어야 한다.
- **FR-052c**: 사용자가 라운드를 직접 중단하는 기능은 제공하지 않는다.

**공통 상태 / 알림**

- **FR-050**: 앱 사용 중에는 상대의 모든 행동(입장, 종료 요청·응답, 제출·채점 완료, 결산 공개, 소원권 요청·응답, 라운드 자동 취소)이 화면에 자동으로 반영되어야 한다.
- **FR-050a**: 앱을 사용하지 않을 때는 상대 입장(방장에게), 종료 요청(상대에게), 소원권 승인 요청(상대에게) 세 가지 이벤트만 기기 알림으로 보내야 한다. 알림을 누르면 해당 응답 화면으로 이동해야 한다.
- **FR-050b**: 기기 알림 문구에는 미션·벌칙·추리 내용을 넣어서는 안 된다.
- **FR-050c**: 사용자가 기기 알림을 허용하지 않아도 게임은 계속 진행할 수 있어야 하며, 앱을 열면 대기 중인 요청이 표시되어야 한다.
- **FR-051**: 주요 단계(입장, 설정, 진행, 추리, 채점, 결산, 소원권)는 로딩·대기·빈 상태·오류·재시도 상태를 제공해야 한다.
- **FR-052**: 모든 설정·선택·응답·결과는 해당 라운드에 귀속되어야 하며, 새 라운드는 이전 라운드 데이터를 이어받지 않는다(스탬프·소원권 제외).

**이용 방법**

- **FR-053**: 대기실에서 이용 방법 화면으로 이동해 게임 규칙을 확인하고 뒤로 돌아올 수 있어야 한다.

### Key Entities

- **사용자(참가자)**: 기기 하나에 대응하는 플레이어. 역할(방장/참여자), 접속 상태, 보유 스탬프 수(0–3), 보유 소원권을 가진다.
- **방**: 연인 두 사람을 묶는 단위. 초대 코드, 정원 2명, 성립 여부, 참가자 목록을 가진다. 여러 라운드를 포함한다.
- **라운드**: 한 번의 게임. 유형(온라인/오프라인), 미션 개수(1–3), 상태(대기 → 설정 → 진행 중 → 종료 요청 → 추리/채점 → 결산 → 완료, 결산 전 어느 단계에서든 → 취소됨), 마지막 활동 시각, 승자/패자를 가진다.
- **미션**: 사용자가 수행할 비공개 행동. 유형(온라인/오프라인)별 목록에서 선택된다. 라운드별로 소유자와 수행 여부(O/X)를 가진다.
- **벌칙**: 상대가 패배 시 수행하도록 사용자가 고른 항목. 라운드당 사용자별 1개, 결산 전 비공개.
- **추리**: 사용자가 상대 미션 하나에 대해 작성한 30자 이내 텍스트. 대상 미션, 작성자, 정답 판정(O/X, 미션 소유자가 판정)을 가진다.
- **종료 요청**: 요청자, 상태(대기/동의/거절/취소)를 가진다. 라운드당 활성 요청은 1건.
- **가위바위보 시도**: 동점 라운드에서의 각 회차. 양쪽 선택과 결과(승/패/비김)를 가진다.
- **스탬프**: 라운드 승리로 적립되는 보상. 적립 원인 라운드와 연결되어 중복 적립을 막는다.
- **소원권**: 스탬프 3개 교환으로 발급. 발급일, 만료일(발급일 + 1개월), 상태(보유/승인 대기/사용 완료/만료). 거절되면 승인 대기 → 보유로 돌아간다를 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 사용하는 커플이 방 생성부터 두 사람 모두 대기실에 입장하기까지 2분 이내에 완료한다.
- **SC-002**: 두 사용자가 도움 없이 방 생성 → 설정 → 진행 → 종료 동의 → 추리 → 채점 → 결산 → 스탬프 적립의 전체 라운드를 완주할 수 있다(테스트 커플 90% 이상 첫 시도 완주).
- **SC-003**: 결산 공개 전까지 어떤 화면·알림에서도 상대의 미션·벌칙이 노출된 사례가 0건이다.
- **SC-004**: 한쪽 기기에서의 행동(입장, 종료 요청·응답, 제출, 채점)이 상대 기기에 3초 이내로 반영된다(양쪽 모두 정상 연결 기준).
- **SC-005**: 모든 테스트 라운드에서 두 기기의 결산 결과(점수·승자·공개 벌칙)가 100% 일치한다.
- **SC-006**: 재시도·재접속·중복 입력 상황에서도 추리·채점·스탬프가 중복 반영된 사례가 0건이다.
- **SC-007**: 앱을 종료 후 다시 연 사용자의 100%가 진행 중이던 라운드 단계로 복귀한다.
- **SC-008**: 잘못된 코드·만원 코드 입력 시 100% 입장이 차단되고 해당 사유가 안내된다.

## Assumptions

- **대상**: 연인 2인 한 쌍. 각자 자신의 스마트폰을 사용하며, 진행 중 두 기기 모두 인터넷에 연결될 수 있다.
- **계정**: 별도 회원가입·로그인 없이 기기 단위로 사용자를 식별한다. 앱을 삭제하면 방 정보가 사라지고 재설치 후 새 방을 만들어야 한다(PRD 4.1).
- **방과 라운드**: 한 방은 성립 후 같은 커플이 여러 라운드를 반복 플레이하는 지속 단위이며, 스탬프·소원권은 라운드를 넘어 누적된다.
- **라운드 설정 권한**: 라운드 유형·미션 개수는 방장만 정한다(PRD 4.2). 참여자는 대기한다.
- **미션·벌칙 목록**: 앱이 기본 제공하는 목록을 사용한다. 유형(온라인/오프라인)에 따라 미션 목록이 구분된다. 사용자 제안 미션·벌칙, 미션 콘셉트 선택은 Should 범위로 MVP에서 제외한다.
- **같은 미션 선택**: 두 사람이 우연히 같은 미션을 고르는 것은 허용한다(서로의 선택을 알 수 없으므로).
- **가위바위보 방식**: 각자 비공개로 선택한 뒤 동시 공개한다.
- **벌칙 수행 시점**: 결산 화면에서 안내만 하고, 실제 수행 시점과 확인은 커플 자율에 맡긴다.
- **종료 요청 무응답**: 요청자가 요청을 취소할 수 있으며, 두 참가자 모두 24시간 동안 활동이 없으면 라운드가 자동 취소된다.
- **알림**: 앱을 사용하지 않을 때의 기기 알림은 상대 입장·종료 요청·소원권 승인 요청 3종으로 한정한다(Clarifications 참조). 나머지 이벤트는 앱 화면에만 반영한다.
- **‘1개월’ 유효기간**: 서버가 정한 만료 시각(`expiresAt`, 발급 시각 + 1개월. 예: 11/21 20:00 발급 → 12/21 20:00 만료)과 남은 일수를 그대로 따른다(`docs/API명세서.md` 21·22번).
- **제외 범위(Should)**: 미션 콘셉트 선택, 사용자 미션·벌칙 제안, 결산 공유, 소원권 내용 제안·입력은 이번 범위에서 제외한다.
- **IA**: 홈을 대기실로 두는 화면 구성은 PRD의 제안을 따르며, 홈/메인 순서는 IA 확정 시 조정될 수 있다.
