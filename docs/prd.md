## 1. 제품 개요와 MVP 목표

힐끔은 연인이 평소와 다른 행동을 미션으로 수행하고 서로 관찰·추리해 결과를 확인하는 데이트 게임이다. 탐정·기밀 문서 콘셉트는 화면 표현이며, 핵심 경험은 ‘미션’과 ‘관찰’이다.

**MVP 목표:** 두 사용자가 각자 기기에서 방 생성 → 설정 → 진행 → 종료 동의 → 추리 → 채점 → 결산 → 스탬프 적립까지 완료한다. 대상은 2인 한 쌍이며 방 정원은 2명이다.

## 2. MVP 범위

### Must

| 기능 | 완료 기준 |
| --- | --- |
| 초기 설정/초대 | 코드 생성·복사, 코드 입력으로 같은 방 입장, 잘못된 코드와 만원 안내 |
| 방 생성 | 온라인/오프라인 유형, 미션 개수 선택 |
| 미션 설정 | 각자 미션 선택, 상대에게 비공개 |
| 벌칙 설정 | 각자 상대가 수행할 벌칙을 선택하고 공개 전까지 비공개 |
| 종료·추리 | 종료 의사 전달 및 상대 동의, 상대 미션을 텍스트로 추리·제출 |
| 채점 | 본인 미션 수행 O/X, 상대 추리 정답 여부를 미션 소유자가 O/X 판정 |
| 결산 | 점수 계산, 승자·패자와 벌칙 공개, 동점 시 가위바위보 |
| 스탬프·소원권 | 승자 스탬프 +1, 최대 3개, 3개 달성 시 교환, 소원권 최대 1장·1개월 유효, 소원권 사용 버튼 클릭 시 상대방에게 사용 승인 알림 |

### Should

> 시간이 충분한 경우 개발
> 
- 미션 콘셉트 선택
- 사용자 미션·벌칙 제안
- 결산 내용 공유
- 소원권 내용 제안·입력

## 3. 용어와 상태

- **방장:** 방을 최초 생성한 사용자
- **참여자:** 초대 코드를 입력해 들어온 두 번째 사용자
- **내 미션:** 내가 수행하고 상대가 추리하는 비공개 미션
- **내 벌칙:** 상대가 패배했을 때 수행하도록 내가 선택한 비공개 벌칙
- **라운드 상태:** 대기 → 설정 → 진행 중 → 종료 요청 → 추리/채점 → 결산 → 완료
- 방은 참가자 2명으로 구성한다. 설정·선택·응답·결과는 해당 라운드에 귀속된다.

## 4. 기능별 규칙과 예외

### 4.1 초기 설정

**규칙**

1. 첫 진입에서 ‘시작하기’ 또는 ‘초대 코드 입력’을 선택한다.
2. 생성자는 새 방을 만들고 코드를 확인·복사한다.
3. 상대는 코드를 입력해 같은 방에 참여한다.
4. 참가자 2명이 모두 입장해야 설정을 시작한다.

**예외**

- 잘못된 코드: 입장시키지 않고 재입력 안내
- 정원 초과: 이미 사용된 코드로 안내
- 중도 이탈·재접속 복구
- 코드 만료: 코드가 사용되어 실제 방이 성립되기 이전에는 해당 코드는 유효
- 방 삭제: 어플 삭제 후 재설치 필요

### 4.2 방 생성

방장은 온라인/오프라인 유형과 오늘 수행할 미션 종류, 미션 개수를 설정한다. 

- ‘미션 시작하기’ 아이콘을 클릭해 새로운 방 생성
- 한쪽만 설정 완료: 설정을 유지하고 상대 대기 표시
- 미션 개수 범위: 1-3개
- 상대 미션이 화면이나 API 응답에 노출되지 않도록 한다.

### 4.3 미션/벌칙 설정

미션 개수 설정 이후에는 각자의 화면에서 자신의 미션/상대방이 수행할 벌칙을 차례로 선택한다. 상대가 선택한 미션/벌칙은 결산 공개 전까지 상대에게 비공개다. 양측 설정이 완료되면 진행 단계로 넘어간다.

- 한쪽만 완료: 상대 대기 표시
- 목록이 비었거나 선택값이 유효하지 않음: 진행 불가 및 재선택 안내
- 미션 개수: *4.2 방 생성* 시 입력한 값만큼 선택 가능
- 벌칙 개수: 1개 고정

### 4.5 진행 및 종료 확인

진행 화면에는 본인의 미션만 표시한다. 한 사용자가 종료를 요청하면 상대에게 확인을 보내고, 상대가 동의하면 추리 단계로 전환한다. 상대가 거절하면 진행 상태를 유지한다.

- 응답 대기·상대 미접속 상태를 구분해 표시한다.
- 중복 요청은 한 번만 처리한다.
- 승인 요청 거절: 기존 진행 화면으로 복귀

### 4.6 추리 입력

종료에 동의한 뒤 사용자는 상대의 미션을 텍스트로 입력해 제출한다. 제출 내용은 상대에게 전달되며 기본적으로 수정할 수 없다. 미션이 여러 개면 미션별 추리와 제출이 필요하다.

- 빈 입력은 제출할 수 없다.
- 한쪽만 제출하면 완료한 쪽에 상대 대기를 표시한다.
- 재전송은 중복 저장하지 않는다.
- 글자 수 제한: 각 미션 별 30자
- 다중 미션 입력 방식: 병렬으로 작성 후 제출
- 제출 후 정정 정책: 불가

### 4.6 채점

각 사용자는 자기 미션을 실제로 수행했는지 O/X로 체크한다. 미션 소유자는 상대가 입력한 추리를 보고 정답 여부를 O/X로 판정한다. 양측 채점이 끝나기 전에는 결산을 공개하지 않는다.

- 상대 미완료 시 대기 표시
- 통신 실패 시 재시도하며 결과를 중복 반영하지 않음
- 수행 여부는 자기 보고 방식이며 별도 확인은 진행하지 않음

### 4.7 결산

수행 여부와 상대 추리의 정답 여부를 반영해 점수를 계산한다. 서로의 응답과 미션, 미션 수행 여부 및 최종 점수를 공개한 후, 승자와 패자를 정한다. 승자·패자 설정 후 승자가 선택한 벌칙을 공개한다.

**결정 필요:** 점수 공식, 점수의 귀속, 여러 미션의 집계 방식이 정해지지 않았다. 가위바위보 입력·공개 방식과 벌칙 수행 시점도 확정 필요

### 4.7.1 동점 처리

동점이면 승자가 가려질 때까지 가위바위보를 반복한다.

- 가위바위보가 비기면 재시도한다.

### 4.8 스탬프·소원권

- 승자에게 스탬프 1개를 적립한다. 스탬프 보유량은 최대 3개다.
- 스탬프 3개를 보유하고 소원권이 없으면 교환 버튼을 활성화한다.
- 교환 시 스탬프 3개를 차감하고 소원권 1장을 발급한다.
- 소원권은 발급일부터 1개월 유효하며 D-day를 표시한다.
- 소원권 사용 시 상대에게 알림을 보낸다.
- 소원권은 최대 1장 보유할 수 있다.
- 소원권 보유 중 추가 승리로 스탬프가 가득 찬 경우
- 승리 스탬프가 가득 차있고, 소원권을 이미 보유하고 있는 경우 경고 문구를 표시한다. 경고 문구는 스탬프가 가득 찬 경우 추가로 승리해도 승리 스탬프를 획득할 수 없음을 알린다
- 소원권 만료 시: 별도의 경고 알림 없이 소원권이 삭제된다

| 9 | 진행 | 내 미션, 진행 상태, 종료 버튼, 상대 종료 요청 수신 |

| 12 | 채점 | 내 수행 O/X, 상대 추리 정답 O/X 판정, 미완료 대기 |
| 13 | 동점 승부 | 가위바위보 선택·결과, 비김 재시도 |
| 14 | 결산 | 승패·점수·공개 미션/벌칙·벌칙 안내·스탬프 반영 |
| 15 | 스탬프/소원권 | 2/3, 3/3 교환 가능, 보유권·D-day, 사용 |
| 16 | 소원권 사용 확인 | 사용 확인·상대 알림, 처리 중·완료·실패 |

**권장 흐름:** 시작/메인 → 방 생성 또는 코드 입장 → 대기실 → 미션 설정 → 벌칙 설정 → 진행 → 종료 확인 → 추리 → 채점 → (동점이면 가위바위보) → 결산 → 스탬프/소원권

Notion은 첫 진입 선택을 정의하고 PRD는 홈과 메인의 순서를 미결정으로 두고 있다. 홈을 대기실로 두는 구성은 IA 확정 전 제안이다.

## 6. 완료 기준

- 두 기기에서 방 생성·코드 입장이 가능하고 잘못된 코드·만원 예외를 처리한다.
- 양측은 서로의 미션·벌칙을 보지 않고 설정을 마친다.
- 종료·동의, 추리, 채점 결과가 상대 기기에 동기화된다.
- 양쪽 결산 결과가 일치하고 승자·패자·벌칙이 표시된다.
- 동점이면 가위바위보로 승부를 결정한다.
- 승자 스탬프가 한 번만 적립되고 보유·교환 상태가 갱신된다.
- 주요 단계에서 로딩·대기·빈 상태·오류·재시도 상태를 제공한다.
